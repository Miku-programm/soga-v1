交互式管理菜单

已核对官方 https://github.com/vaxilu/soga ：install_cmd.sh 下载
https://github.com/vaxilu/soga-cmd 的管理程序；根目录 soga.sh 是旧版单实例菜单。
截至本次核对，soga-cmd 仓库只提供 README 和发布程序，未公开菜单源码。
这里按用户提供的新版多实例菜单独立实现，并接入本重建工程。

安装后输入 soga，即可显示与提供的菜单相同的顶层布局：
0 退出；1 安装/更新；2 完全卸载；3 切换稳定/测试分支；
4 更新管理脚本；5 新增实例；6 起按实例列表进入对应实例管理。
支持直接输入实例名。列表显示真实运行状态、自启状态及配置文件路径。
实例二级菜单按官方 0–15 布局：启停、重启、重载、状态详情、最近/实时日志、
开关自启、快速配置，以及编辑 soga.conf、blockList、whiteList、routes.toml、dns.yml。
重命名和删除实例仍可使用 soga rename / soga remove 命令。
重载发送 HUP，刷新面板数据和规则；soga.conf 改动通过重启生效。
快速配置回车保留值、输入 - 清空，通讯密钥输入隐藏；保存后可选择重启。
default 不能重命名或删除。完全卸载需输入 y 或 Y 确认，会删除本重建版配置。
直接运行 scripts/uninstall.sh 仍保留配置；与菜单的「完全卸载」用途不同。

管理器使用 Python 3 标准库；真实安装缺少 Python 3 时通过系统包管理器安装。
管理器版本单独显示，不冒充原版 v0.0.6；程序版本标注「重建版」。
命令入口为 /usr/bin/soga；程序为 /usr/local/soga/soga。
默认配置 /etc/soga/soga.conf，其他实例 /etc/soga/实例名/soga.conf。
默认服务 soga.service，其他服务 soga@实例名.service，与官方布局一致。
保留已有 /etc/soga 配置；不存在默认配置时迁移之前的 /etc/soga-reconstructed，
保留旧目录，并停用之前重建版服务，防止端口冲突。
覆盖的程序、菜单及服务文件备份在 /var/backups/soga/时间戳-进程号/。
/usr/local/bin/soga 保留为转发到 /usr/bin/soga 的兼容入口，避免旧 Bash 命令缓存失效。
如果该位置是其他程序，安装会明确报错，避免误删。

稳定版取 GitHub 最新正式 Release；测试版取最新非草稿预发布。
维护者可在 Actions 手动运行时选择 preview，生成真正的测试版 Release。
没有测试版时会明确提示，不会将稳定版冒充测试版。
交互式终端安装结束后自动打开菜单；SOGA_NO_MENU=1 可关闭自动打开。
从菜单内更新不再嵌套打开新菜单。终端显示彩色菜单，重定向输出保持纯文本。
旧服务列表为空时 systemctl 的状态码 1 按无旧服务处理；真实错误会明确报出。
旧服务仍在 systemd 列表但文件已不存在时，跳过 disable；如仍有活动实例，
先停止再迁移。残留失败记录尝试重置；真实停止或取消自启失败仍明确报错。
检查更新失败不会阻止实例管理；自更新管理脚本会验证发布包 SHA-256。
管理脚本更新后重新运行 soga；程序更新会复用默认实例配置并重启默认实例，
其他运行实例如需切换至新程序，请在各自菜单中重启。

也支持命令：soga list / new / remove / rename / start / stop / restart /
enable / disable / status / log / config / update / uninstall / self-update / version。
例如 soga log anytls -f、soga restart anytls。

这是独立兼容重建工程，不是原作者源码。原始 soga 二进制没有上传。
用户要求保留现有业务实现；安装流程参照官方脚本的版本参数、配置写入及自动启动行为。
参考：https://github.com/vaxilu/soga/blob/master/install.sh
不是官方脚本原样副本：下载源、包结构、程序本体和管理器适配本重建工程，
保留 SHA-256 校验；配置写入不会回显密钥。不会安装官方原版程序或 soga-cmd。
已知 v2node 配置接口差异未修复，不承诺兼容 wyx2685/v2board 最新版 v2node。
validation/ 是原本地交付的历史验收记录；每次 GitHub 构建的检查结果随 Release 发布。

一键安装（Linux amd64/arm64）

  bash <(curl -Ls https://raw.githubusercontent.com/Miku-programm/soga-v1/main/install.sh) type=v2board server_type=vmess \
    webapi_url=https://你的面板域名 webapi_key=你的通讯密钥 node_id=1

以上为普通 V2Board VMess 节点示例；面板类型、协议和节点 ID 必须改成实际值。
命令会写入配置并自动启动；不需要再手动编辑文件或执行启动命令。
密钥若含特殊字符，请用 shell 引号包住整个 webapi_key=... 参数。
以 root 执行以下命令安装或更新，然后输入 soga 打开管理菜单：
  bash <(curl -Ls https://raw.githubusercontent.com/Miku-programm/soga-v1/main/install.sh)
已有配置时保留配置并重启；全新安装需要提供实际节点配置。

也可以给安装脚本传一个 Release 标签，安装固定版本：
  bash <(curl -Ls https://raw.githubusercontent.com/Miku-programm/soga-v1/main/install.sh) build-1-1-abcdef0
以上标签只是格式示例；实际标签以 Releases 页面为准。

真实安装支持 apt/dnf/yum，自动安装依赖及 acme.sh，并设置 Let’s Encrypt 默认 CA。
脚本识别架构、下载 Release、校验 SHA-256，然后安装程序及 systemd 模板。
配置参数可与版本参数混合排列，同名参数以后面的值为准。
已有配置会保留，仅覆盖显式传入的字段；已有配置或传入参数时自动重启。
首次未传任何配置参数时，仍按官方流程提示先配置，不启动空配置实例。
真实安装会设置开机自启；DESTDIR 临时目录安装不操作宿主 systemd。
已有安装的默认路径为 /etc/soga/soga.conf。

key 的区别

webapi_key：填机场面板的后端通讯密钥。对于 wyx2685/v2board，
在后台系统配置的「节点」页签找到「通讯密钥」（源码字段 server_token）。
把面板里已有的值填入本机配置，不能随意填一个不同的值。
此密钥无需用于 GitHub 编译，也不要写入公开仓库或 Actions 配置。

soga_key：原版商业授权字段。本独立重建工程不调用原商业授权服务，留空即可。
soga_panel_key / soga_panel_url：未恢复的自动配置服务，均留空。
tunnel_password：仅开启隧道时使用，必须与对端隧道配置一致。

常规 V2Board VMess 节点配置示例（不是 v2node 示例）

  type=v2board
  server_type=vmess
  api=webapi
  node_id=1
  webapi_url=https://你的面板域名
  webapi_key=面板后台的通讯密钥
  soga_key=
  soga_panel_url=
  soga_panel_key=

webapi_url 填面板基础地址，不要追加 /api/v1/server/UniProxy/config。
node_id 和 server_type 应与面板创建的节点一致。
手动配置时使用以下命令；安装脚本带参数运行时已自动完成：
  sudo systemctl enable --now soga
  sudo journalctl -u soga -f

GitHub 编译

推送 main 自动发布稳定版，也可进入 Actions → Build Linux programs → Run workflow，
选择 stable 或 preview。稳定版更新 latest；测试版标记为预发布，不覆盖 latest。
Go 1.27.3 使用仓库内 vendor 离线构建两个架构。
amd64 执行 CLI、本地进程及管理菜单测试；arm64 只交叉编译，不冒充原生运行验证。
一键安装入口另验收临时目录安装、配置保留及参数写入、密钥不回显、
损坏下载包拒绝安装，以及通过命令替身验证首次/升级/失败的服务启停流程。
成功后生成 Release，提供裸程序、带安装文件的 tar.gz、完整源码 tar.gz、
检查报告和 SHA256SUMS。无需填写任何面板密钥或商业 key 即可编译。
